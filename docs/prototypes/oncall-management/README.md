# Oncall Web 原型

用于讨论产品方向的静态 HTML 原型。当前范围收敛为只读管理页，尚未接入真实机器人。

## 当前方案

- A 运行概览：查看话题暂停情况、当前执行、排队数量与最终回复发送状态。
- B 案例库：搜索案例，查看逐条结论的验证状态、文本证据和来源轮次。
- C 话题记录：切换话题及执行轮次，查看各轮请求、结果、进展、结论与证据。
- 工作区：只读展示群聊／私聊绑定、仓库、知识资料路径及执行配置。

用户操作仅包括导航、搜索、筛选、打开详情和切换查看的轮次。发起分析、补充上下文、停止与继续仍通过既有飞书入口；网页不新增执行命令入口。

## 状态与数据语义

四个维度分别展示，不能互相推断：

1. 话题是否暂停：对应 `oncall_topics.paused`。话题已暂停时，当前执行可能仍在停止中，队列仍保留。
2. 单轮执行：对应 `jobs.execution_status`，使用 preparing、queued、running、cancel_requested、succeeded、failed、cancelled、interrupted。原型显示友好中文标签。
3. 最终回复发送：从该轮最终回复的投递记录读取 pending、delivering、delivered、abandoned。执行成功不代表回复送达；没有记录显示“暂无最终回复”。不能将状态卡片的早期投递成功当作最终回复送达。
4. 每条结论的验证状态：来自 `conclusions[].verification`，区分 observed、verified、unverified。缺失则不显示，不能从回复中的提问推断等待用户输入。

概览的当前轮次优先选正在准备／执行／停止的轮次，否则选最新请求。排队数量单独统计。执行占用包含 running 和 cancel_requested；关注筛选包含话题暂停、当前执行异常／停止中，以及该话题任意轮次的最终回复发送失败。

详情上方始终展示话题当前概况，下方明确标出正在查看的轮次。结论和证据按 jobId 关联；历史轮次没有案例数据时显示空证据，不借用其他轮次的结论。生产接入需要联查 `oncall_case_history` 和任务记录，不能只读取当前案例表。案例入口直接定位来源轮次。

证据按字符串原文展示，不虚构日志、截图、文件查看器。只有原文包含合法 HTTP(S) URL 时才生成可点击链接；文本名称本身不可点击。来源是 Agent 保存的记录，不代表网页重新取证验证。

服务区域只显示进程状态与带时间的快照，不能推断飞书实时连接或业务工具可用性。原型不提供业务工具绿灯和虚构检查时间。

## 启动

无需安装或构建。当前静态服务使用端口 6192：

```sh
python3 -m http.server 6192 --bind 0.0.0.0 --directory docs/prototypes/oncall-management
```

- A：http://localhost:6192/?view=console
- B：http://localhost:6192/?view=cases
- C：http://localhost:6192/?view=desk
- 工作区：http://localhost:6192/?view=workspace
- 停止中且有排队请求：http://localhost:6192/?view=desk&topic=OC-026
- 具体历史轮次：http://localhost:6192/?view=desk&topic=OC-025&job=JOB-177

桌面浏览器此前直接访问 localhost:6192 返回连接拒绝；用户桌面的可达性仍未验证。可以从当前远端终端打开链接，使用 Runweave 本地页面预览通道；不支持该通道的客户端需要配置 6192 同号端口转发。

## 模拟数据与实现边界

所有展示数据来自 `mock-state.json`。人员、标题、分类、编号、配置、时间、健康快照和任务状态都是展示样例，不表示当前线上事实。样例 health 的 fresh 是固定展示状态，真实实现需按采样时间计算过期。标题、分类和友好编号为展示字段，尚未声明为现有后端字段。

原型在 JSON 中按话题嵌套 jobs，并用 replyState 简化最终回复投递记录；这是只读展示模型，不是改写现有数据库或生产 DTO 的提案。真实字段来源需以 `src/contracts.ts`、`src/oncall/store.ts`、`src/oncall/case-store.ts`、`src/health.ts` 和 `src/oncall/workspace-config.ts` 为准。

当前仅获取静态文件，没有机器人 API、生产数据库读写、飞书消息发送或配置更新。真实只读 API、身份验证和可见范围仍需在后续实施中完成。不得从原型反推这些能力已经实现。

## 功能分类账

| 类别 | 元素 | 处理 |
|---|---|---|
| 产品候选 | 话题／执行／投递概况、搜索和筛选 | 从真实记录生成只读视图 |
| 产品候选 | 多轮历史、逐条结论、文本证据、来源轮次导航 | 保留真实轮次关联与缺失数据 |
| 产品候选 | 工作区配置与服务快照 | 只读；不推断工具可用性 |
| 原型辅助 | `?view=`、`?topic=`、`?job=`、`?case=` 及 JSON 样例 | 仅用于原型导航与展示 |
| 原型辅助 | 固定时间、友好编号、人员和配置样例 | 不作为生产事实 |

## 已放弃的原型行为

- “待补充 / 待确认”作为执行状态，以及由此产生的自动催办统计。
- 单一话题状态包办执行、结论与回复送达的含义。
- 暂停／继续、发送并分析、补充上下文、修订结论、编辑关联和保存按钮；相关事件处理与本地业务状态修改已删除。
- 业务工具可用绿灯、虚构的检查时间、机器人在线断言。
- 将证据名称画成可打开的日志／文件，把当前案例强行展示到所有历史轮次。
